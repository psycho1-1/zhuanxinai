# 砖芯 AI P0：教师审查与两轮可用性试点工作包

日期：2026-09-11。文件状态：可填写模板。**当前没有已招募的教师或学生，没有完成的审查记录，也没有学习有效性结论。** 方括号内容由负责人填写；未填或未核对项不能当作已完成。

用途：先核对有理数小范围的数学内容、诊断分支和产品操作，再决定是否进入后续有效性研究。本文件不发送招募消息，不自动收集个人资料、不录屏录音、不承诺法律合规或学习提分。

## B. 内容审查表填写规则

配套 CSV 没有示例数据或假记录，只有列名。每位审查者保存独立文件，版本变更后新增审查行，保留旧行并标为失效，不悄悄覆盖。

| 字段 | 怎么填 |
|---|---|
| review_id / reviewed_at | 唯一审查编号与实际时间；尚未审查保持空白 |
| release_version / content_version / policy_version | 实际审查的冻结版本 |
| asset_type / item_id / card_id | `item`、`probe`、`intervention_card`；填对应稳定 ID |
| reviewer_alias / review_round | 审查者别名与实际轮次；别名映射由负责人单独保管 |
| mathematical_accuracy | `pass / revise / reject / insufficient`；公式、边界、零/负数等检查 |
| answer_uniqueness_and_alternatives | `pass / revise / reject / insufficient`；多解、等价表达、选择题歧义 |
| misconception_mapping | `supported / contradicted / insufficient / not_applicable`；一个错答不直接等同唯一原因 |
| item_family_and_transfer | `pass / revise / insufficient`；换数字题是否同族，是否可声称迁移 |
| prerequisite_mapping | `supported / contradicted / insufficient / not_applicable`；区分严格前提与教学建议 |
| age_readability | `pass / revise / insufficient`；七年级阅读负担和符号清晰度 |
| intervention_fit | `supported / contradicted / insufficient / not_applicable`；帮助是否针对证据，是否直接泄露复测答案 |
| source_and_rights | `checked / needs_check / not_applicable`，并填来源说明；不是法律授权结论 |
| severity | `critical / major / minor / none / insufficient`；数学误导或泄漏独立测验通常至少 major |
| overall_verdict | `approve / revise / reject / insufficient`；`approve` 是内容审查结论，不是学习效果证明 |
| evidence_and_reason / suggested_change | 指出具体句子、步骤、选项和修改建议，避免仅写“挺好” |
| adjudication_required / disposition | `yes / no`；处理状态 `open / revised_pending_review / closed` |

审查者可以指出教学依据不足，即使答案正确也不必批准诊断规则。负责人汇总中始终保留原始审查意见。

### 可用性任务卡与观察表

主持人先给目标，不给按钮位置。只有学生请求帮助或明显受阻时才指导，并把该任务标记为“有帮助”，不能算独立完成。

| 任务 | 对学生说的话 | 记录字段 | 通过判断 |
|---|---|---|---|
| T1 自主开始 | “选一个你愿意看的有理数内容，开始学习。” | 完成/求助/退出；位置误解 | 找到自选课程，不要求选推荐课程 |
| T2 理解推荐 | “看看网站为什么建议你看这一点，用自己的话说一下。” | 学生原意摘要；是否误解为能力判决 | 能指出具体作答证据；不把猜测理解成永久标签 |
| T3 跳过诊断 | “如果你现在不想回答这道追问，试试继续学习。” | 是否找到跳过；是否有惩罚措辞 | 可以继续；跳过不记答错或扣掌握度 |
| T4 纠正推荐 | “假如你觉得这个原因不符合你的情况，试试告诉网站。” | 入口是否存在；反馈是否保存 | 反馈路径明确；未实现则记录缺陷，不替网站解释 |
| T5 换讲解/返回 | “换一种帮助，或回到你刚才的课程。” | 返回后题目/记录是否丢失 | 选择可理解；没有无限强制诊断 |
| T6 暂停/结束 | “现在你想休息，看看怎么结束。” | 是否担心扣分；残留弹窗 | 能结束，不诱导连续时长，不处罚退出 |
| T7 删除/撤回演练 | 由监护人和负责人使用测试档案演练 | 请求号、覆盖对象、完成时间、恢复结果 | 请求可安全提交，真实范围和备份限制可说明 |

观察笔记只记完成任务所需的事实，尽量用简短摘要，不记录无关家庭或健康信息。每次诊断最多两次连续追问后主动提供退出；约 3 分钟是初始负担上限提案，可由观察修订。

### 试点结束语

AI 费用估计：`请求数 × (平均输入 token × 输入单价 + 平均输出 token × 输出单价) / 1,000,000`，缓存单独计价时拆开；失败请求是否计费按实际账单。不要将每次调用与每次学生提问当作永久一一对应。

当前全站每日 500 次限制是设计约束。100 DAU × 20 次答题 × 25% 干预 × 每次 2 调用 = 1,000 调用/日，是一种会超限的假设负载，不是当前实测；规则诊断和静态补救应零模型调用。任何提高上限都需要基于真实成本再决定。
