# 跟着第一版学编程

## 第一步：看懂入口与组件

先看 `app/page.tsx`。它返回 `<LearningApp />`，可以把它理解为“在这里显示学习应用”。真正的界面放在 `components/learning-app.tsx`。

React 组件是返回页面内容的函数。`LearningApp` 管理三个视图：学习路径、错题本、学习进度。`Practice` 负责一轮练习。`Stat` 显示一个统计数字，这样同一种样式不用复制多遍。

`useState` 保存页面当前状态，例如输入答案 `answer`、当前题号 `index`、判题结果 `result`。调用 `setAnswer` 后，React 会更新相关界面。它们只表示当前页面状态，真正需要长期保存的学习记录在数据库中。

**试一试：** 修改课程页面的副标题，保存后看页面自动更新。

## 第二步：改内容，不动判题逻辑

`lib/curriculum.ts` 中每个知识点都有唯一 `id`，通过 `chapterId` 归属于某个单元。`concept` 是讲解，`example` 是例子，`hint` 是固定提示。

`server/questions.ts` 里的每行练习由题干、数值答案、解析、可选单位构成。例如：

```ts
['|−8| 等于多少？', 8, '−8 到原点的距离为 8，所以 |−8| = 8。'];
```

当前题目 ID 由知识点 ID 和数组位置组合而成。已经产生真实记录以后，不要插入、删除、重排既有题目，也不要把旧题 ID 换成另一道题，否则历史记录会错误关联。新增内容应追加；将来正式做题库编辑器时，改为显式、稳定的题目 UUID 和题目版本。

**试一试：** 先只修改一段解析文字，然后提交对应题目查看效果。初次添加题目时还需要更新题库数量断言，以及当前首页的 45 题和 5 题提示；下一步可以把这些展示数量全部改为数据驱动。

## 第三步：看懂判题函数

`lib/grading.ts` 分成两个函数。

1. `parseAnswer` 把文字转换成一个数。它会处理全角数字、中文环境常见负号，以及 `1/2` 这样的分数。空白、零分母、代码和 `1+2` 这样的表达式会被拒绝。
2. `gradeAnswer` 比较解析后的数值与标准答案，小于 `1e-9` 的差值视为相同，用来容忍浮点表示误差。

这里故意不运行学生输入的代码，也不接收任意代数表达式。题库中的合并同类项题让学生填写系数，因此仍能使用数值判题。以后需要判断 `2x + 3x` 与 `5x` 等价时，应增加独立的符号判题器。

**试一试：** 在绝对值的分数题输入 `2/4`；它应与 `1/2`、`0.5` 一样被判对。输入 `1/0` 应提示格式错误，并且不增加答题次数。

## 第四步：理解服务端与数据库

`app/api/learning/route.ts` 导出 `GET` 和 `POST`。

- GET 返回题干、历史最近答案、各知识点进度和答题统计。第一次访问时，服务端生成随机学习身份，并写入 HttpOnly Cookie；网页脚本无法直接读取这个 Cookie。
- POST 接收题目编号和答案，独立校验后判题。数据库查询使用占位符 `?` 和 `.bind(...)` 传入数据，不把答案拼接成 SQL。
- 同一个提交请求携带固定 `requestId`。数据库中的“学习者 + 请求编号”唯一索引防止网络重试时插入两次。

`db/schema.ts` 描述表结构，但不会在每次访问网页时创建表。`npm run db:generate` 生成迁移 SQL，`npm run db:setup` 在本地执行迁移。已经在线上执行的迁移和其元数据应保持不变，以后追加新迁移。

**试一试：** 故意答错，再到错题本答对。查看掌握度变化，刷新页面确认结果仍在。

## 第五步：理解掌握度

`lib/progress.ts` 把题目和每题最近一次答案放在一起计算。条件判断决定“未开始 / 学习中 / 需复习 / 基础掌握”。可以先读测试中的例子，再读函数。

现在用 5 道不同题作为一个小练习集。后续可以增加独立测验题、按难度分层、间隔复习、迁移题和遗忘曲线。不要把简单正确率直接声称为学生真实能力。

## AI Tutor 怎么接入

`server/tutor-contract.ts` 已定义未来服务应接收与返回的类型，但没有实现或调用真实模型，也没有产生 API 费用。当前固定提示来自 `lesson.hint`。

后续实现顺序：

1. 新增服务端 Tutor API，复用匿名身份或未来的正式账号。
2. 服务端根据 questionId 读取题目、知识点和本人的尝试记录；不要相信客户端提供的“正确答案”。
3. 实现 TutorProvider，以当前知识点为范围，先提问或分层提示。
4. 对返回内容做验证，增加超时、调用频率与费用上限、失败后的课程提示回退。
5. 用教师审校的典型错题检验提示是否正确、是否过早泄露答案，再接入对话界面。

密钥只保存在服务端部署密钥中，不写入页面、代码仓库或公开环境变量。本期没有需要填写密钥的文件。

## 从初一扩展到 K12

当前只有一个初一数学课程。扩展时先增加以下实体，而不是复制很多个独立网站：

```text
学段 → 年级 → 学科 → 教材版本 → 课程 → 单元 → 知识点 → 题目版本
```

给知识点增加先修知识点列表，得到可以计算的有向学习关系；第一版现在只有单元归属与推荐顺序，没有实现知识图谱算法。给内容增加审核状态，教师确认后再发布。

下一阶段建议优先做：教师审校样例内容、明确教材版本、补全一个单元、正式账号与进度找回，再小范围验证 AI 提示。正式向未成年人提供服务之前，需要结合实际运营地区评估账号、监护人安排、数据管理与访问体验。
